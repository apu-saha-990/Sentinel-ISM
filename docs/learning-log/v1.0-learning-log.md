## Notes (dated, as we go)

**2026-08-28 — The six ISM controls, plain-language understanding**

- **ISM-0383 (unneeded accounts/services disabled):** unused accounts and running services are extra attack surface for no benefit. Check lists every account and enabled service, compares against an allow-list, flags anything unexpected.
- **ISM-1508 (privileged access limited):** fewer accounts able to `sudo` means smaller blast radius if one gets compromised. Check looks at sudoers group membership, flags if it grows unexpectedly.
- **ISM-0584 (logon/failed logon/logoff logged):** confirms the system is actually recording login activity, via `/var/log/auth.log` existing, being written to, and non-empty.
- **ISM-1985 (logs protected from unauthorised access):** log files need to be unreadable by random users, or sensitive info (login patterns, attack attempts) leaks. Check is file permissions — not world-readable.
- **ISM-1815 (logs protected from unauthorised modification/deletion):** if a compromised low-privilege account can write to the log, an attacker can cover their tracks. Check is file permissions — not world-writable.
- **ISM-0988 (accurate/consistent time source):** wrong or drifting clocks make log timestamps useless for correlating events, and can break certificate validation. Check confirms a time-sync service (chrony/systemd-timesyncd) is actually running and synced, not just installed.

**Why these six specifically:** all of them are things directly observable on the machine right now (a file's permissions, a service's state, an account list) — none require judging intent or paperwork/process, which is why the original longer ISM list got trimmed down to these.
